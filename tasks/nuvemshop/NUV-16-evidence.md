Whole-lockfile audit reports the same six pre-existing findings on baseline and candidate (Vitest/mocker/coverage, Vite, undici, Zod); no automatic audit fix or unrelated upgrade was performed.

Private schema `nuvemshop_intake`; object owner and runtime are separate restricted NOLOGIN roles initially. Runtime login/credentials and any remote role provisioning require their own approved plan. The SQL grants migration authority SET, without automatic inheritance, on the newly created owner only. Runtime never receives that membership. No function/SECURITY DEFINER or authored trigger is needed.

`receipts` stores local UUID attempt identity, family/contract version, strict normalized JSONB projection, policy references, DB intake time, generated terminal/work identity and hold metadata. `work` stores the same receipt key and initial state; its normalized intention is recovered by JOIN, avoiding divergent payload copies. Generated receipt work identity plus two deferred FKs require both directions at COMMIT and forbid work for unknown receipts. CHECK expressions use `IS TRUE` to reject missing/NULL fields.

Runtime has SELECT plus INSERT on explicitly allowed input columns, FORCE RLS on both tables, no UPDATE/DELETE/TRUNCATE/administrative DDL and no object ownership. PUBLIC/API roles receive no ledger privileges; effective inherited privileges in the shared remote project remain a transport/security gate. Schema is absent from the observed remote Data API configuration.

One acquired `pg` client performs BEGIN, writes and COMMIT/ROLLBACK. Every unconfirmed COMMIT is a typed, sanitized indeterminate error; the client is destroyed. There is no automatic new attempt identity or assertion that the receipt does not exist. Reconciliation uses the same attempt ID on the supplied primary pool; an absent read alone cannot establish that an earlier uncertain transaction has aborted. Reusing an ID with a different normalized projection or policy fails safely; identical content with another attempt ID is a distinct legitimate receipt.

The pool accepts explicit Connect metadata, session mode/5432, trusted TLS with `rejectUnauthorized=true`, bounded connections and query/lock/connection/idle limits. No connection-string options can override TLS. No DSN is inferred from project ref, no process configuration is activated and no admin credential is substituted.

Versioned retention policy constants explicitly map business/lifecycle/unknown v1 to minimum 14 days since intake and terminal, retaining to the later date; replay window 7 days since intake. Work terminal metadata is present for NUV-17 to activate through its reviewed transition migration. No nonterminal/quarantined/held work is eligible for purge. No purge/replay job is implemented. Future families extend family/version/projection validation through an additive migration, retaining the same transaction and links; HR-08 privacy projections and retention remain undecided and absent.
